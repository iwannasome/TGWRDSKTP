# Понятные выводы и быстрый выбор года

Дата: 2026-07-13

Ветка: `agent/year-cache-and-insight-clarity`

## Зачем сделано

На крупном архиве каждый выбор года заново запускал полный анализ базы, включая неизменяемый период «за всё время». Из-за этого обычное переключение в Wrapped ощущалось как повторная сборка отчёта. Одновременно два поведенческих слайда нуждались в более строгом и понятном объяснении результата.

## «Ночной собеседник»

Для победителя теперь обязательно не менее `3000` сообщений в выбранном периоде. Это порог общего объёма диалога, а не только количества ночных сообщений.

После порога объёма остаются прежние проверки качества:

- достаточно сообщений внутри ночного окна;
- ночная доля минимум на 3 процентных пункта выше обычной ночной доли всего архива;
- победитель выбирается по сочетанию превышения над архивным ритмом, ночного объёма и доли.

В evidence отчёта записываются фактический объём и оба минимальных порога. Синтетический тест отдельно проверяет, что победитель и все кандидаты имеют не менее `3000` сообщений.

## «Самый стабильный диалог»

Стабильность здесь означает только равномерность месячного ритма. Это не вероятность, не оценка отношений и не психологическая характеристика.

Для каждого календарного месяца между первым и последним сообщением строится объём `count`. Пустые месяцы остаются в последовательности как нули. Затем считаются:

```text
average = среднее сообщений за календарный месяц
deviation = среднее абсолютное отклонение от average / average
stability = 1 - min(1, deviation)
```

Поэтому стабильность `46,4%` означает среднее нормализованное отклонение `53,6%`. Чем ровнее месяцы относительно собственной средней линии диалога, тем ближе результат к `100%`.

Итоговый рейтинг кандидатов:

```text
coverage × 60
+ stability × 60
+ active_months × 8
+ min(40, active_days / 2)
```

До рейтинга кандидат обязан пройти минимальный объём, число активных месяцев, календарное покрытие и порог стабильности. Слайд теперь показывает эти пороги и человеческое объяснение формулы вместо простого повторения четырёх чисел.

## Кэш и фоновая подготовка годов

Каждый рассчитанный год сохраняется отдельно:

```text
<Electron userData>/report-cache/v1/report-YYYY.json
```

`report.json` остаётся активным отчётом, который открыт сейчас. Все JSON-файлы записываются через временный файл и атомарную замену, поэтому незавершённый расчёт не должен оставлять наполовину записанный отчёт.

Поведение интерфейса:

- через 900 мс после открытия Wrapped worker начинает готовить соседние годы в фоне;
- ближайшие к выбранному годы получают более высокий порядок в очереди;
- выбор неподготовленного года прерывает текущую фоновую задачу и получает приоритет;
- готовый год активируется из дискового кэша без повторного анализа базы;
- список показывает состояния `готово`, `готовим` и `по запросу`;
- старый отчёт без текущей ревизии один раз пересобирается, чтобы новые пороги не оставались только в коде.

Кэш входит в локальный lifecycle: он очищается при новом импорте, пересборке отчёта и полном удалении данных. Сетевых запросов, телеметрии и облачного хранения не добавлено.

## Проверка

Полный локальный gate:

```bash
npm run verify
```

Результат:

- PASS — TypeScript;
- PASS — 5 worker fixture tests;
- PASS — synthetic schema, метрики и повторное открытие годов из кэша;
- PASS — PyInstaller worker и binary smoke;
- PASS — electron-builder package и проверка содержимого;
- PASS — packaged Electron получил `pong` от встроенного worker и подтвердил готовность renderer.

Chrome в текущем окружении не установлен, поэтому встроенные Chrome screenshot-проверки synthetic suite были помечены как skipped. Новый слайд стабильности и открытый список годов дополнительно проверены через настоящий Electron renderer при разрешении `1360 × 900`: переполнения и выхода popup за панель не обнаружено.
