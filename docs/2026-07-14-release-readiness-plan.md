# TGWR 0.2 — релизная готовность

Этот документ — рабочий checklist для beta/release-кандидата. Его цель не в том, чтобы добавить больше слайдов: выпуск должен доказуемо проводить человека от пустого приложения до локального Wrapped, понятного экспорта и полного удаления данных.

## Граница работ

- Telegram ID, намеренно исключённые из people-аналитики, остаются захардкоженными.
- Календарь и время остаются в московском часовом поясе UTC+3.
- Реальные личные экспорты допускаются только для локальной проверки. Их содержимое, имена, ID, пути и результаты не попадают в Git, issues, PR или логи CI.
- Каждая находка получает уровень: **P0** (потеря/утечка данных или запуск невозможен), **P1** (друг не может уверенно пройти основной путь), **P2** (заметное, но не блокирующее улучшение).

## Базовая точка

Проверено на базе `fix/full-project-stabilization` после слияния PR #6 и PR #7:

```bash
npm run verify
```

Результат: PASS для TypeScript, worker fixtures, synthetic metric contract, PyInstaller worker, package contents и smoke упакованного Electron-приложения. Локальные screenshot/browser-подтесты корректно skipped, потому что в машине аудита нет Chrome; в CI они должны остаться обязательными.

## Последовательность gates

### 1. Первый запуск и онбординг

- Чистое приложение объясняет, как получить Telegram Desktop Export, какой формат предпочтителен и что TGWR не требует пароль или код Telegram.
- Отмена выбора папки не меняет состояние.
- Выбранная папка подтверждается без показа технического пути по умолчанию.
- Сбой worker показывает понятное действие для пользователя, а не внутренний жаргон.
- Повторный запуск с готовым отчётом предлагает понятный выбор: открыть, собрать новый из имеющейся базы или стереть всё.

### 2. Импорт и жизненный цикл данных

- JSON, HTML, split JSON, пустые/повреждённые части, группы, каналы, дубликаты и частичный экспорт дают ожидаемый итог или объяснимую ошибку.
- Новый импорт не смешивается со старой базой.
- Длинный импорт можно отменить; после отмены приложение остаётся пригодным для следующей попытки.
- «Пересобрать отчёт» не удаляет базу; «Стереть все данные» удаляет DB, WAL/SHM, отчёты и кэш, включая legacy-location.

### 3. Логика Wrapped

- Реальные и synthetic-данные подтверждают год, ALL, неполный текущий год, кэш/предзагрузку и отмену смены года.
- Каждый вывод имеет достаточную выборку и понятное объяснение; маленькие чаты не становятся случайными победителями.
- Пустые состояния не маскируются выдуманным инсайтом.

### 4. Интерфейс и доступность

- Проверяются все 14 слайдов, Details, People, Share Preview, три темы, узкое окно и длинные имена/тексты.
- Клавиатурная навигация, фокус, подписи кнопок и обновления прогресса доступны без мыши.
- Основной UI говорит по-русски и не показывает пользователю пути БД, имена внутренних файлов или необходимость Python.

### 5. Экспорт и шаринг

- PNG, PDF и insight-card создаются только в папке, выбранной в текущем сеансе.
- Share Preview действительно скрывает выбранные имена, фрагменты и даты и не оставляет их на экспортируемой картинке.
- Отмена системного диалога, повторный экспорт и конфликт имён не ломают приложение и не пишут в неожиданную папку.

### 6. Надёжность и скорость

- Крупный архив проходит импорт в приемлемое время с понятным прогрессом.
- Годы после первого открытия берутся из дискового кэша; пользовательский выбор имеет приоритет над фоновой предзагрузкой.
- Закрытие/перезапуск во время импорта, отчёта и очистки не приводит к поломанному состоянию или ошибочному старому Wrapped.

### 7. Дистрибутивы и документация

- Чистая Windows x64, macOS Intel, macOS ARM64 и Linux x64 получают нативный worker именно своей платформы.
- Установленный artefact запускается без Node.js/Python, импортирует fixture, экспортирует файл и удаляет данные.
- Версия в package metadata, UI, worker, тег и release notes совпадает.
- README и короткая beta-инструкция позволяют другу пройти путь без голосового сопровождения.

### 8. Финальный аудит приватности и безопасности

Этот gate запускается после продуктовой приемки, но P0-находки из других этапов исправляются сразу.

- Electron: sandbox, contextIsolation, preload API, navigation/new-window, IPC validation.
- Файлы: выбор папок, capability-токены экспорта, path traversal, симлинки, очищение userData и legacy files.
- Worker: JSONL validation, отмена, повреждённый вход, ошибки и отсутствие утечек личного содержимого в stdout/stderr.
- Поставка: зависимости, lockfile, секреты, GitHub Actions permissions, неподписанные artefacts и план code signing/notarization.
- Модель угроз и остаточные риски фиксируются отдельным документом до тега.

## Условие выпуска

Release candidate можно пометить готовым, только когда:

1. нет открытых P0/P1;
2. `npm run verify` и CI matrix прошли на финальном commit;
3. ручная приёмка установленных artefacts проведена на доступных чистых системах;
4. приватность/безопасность прошли финальный gate, а неподписанные сборки явно маркированы до подключения сертификатов;
5. beta-инструкция и известные ограничения опубликованы вместе со сборкой.
